# 详细工作流程（references/workflows.md）

## 流程A：周期竞品动态调研报告（最高频）

1. **定窗口**：确认今天日期（终端 `date`），声明监测区间=上一期截止日次日→今天；向用户口头确认窗口。
2. **读状态**：读 `state/research-state.json`（上期截止/去重规则）与 `state/report-index.json`；读 `data/events.jsonl` 已收录事件。
3. **检索布控（按企业优先级）**：
   - 读 `config/companies.json`：`priority=core`（10家核心竞品）**逐家独立检索**（每家至少1组词，不与其他企业混搜），`priority=watch`（153家）按方向合并批量检索即可；
   - 叠加 knowledge.md §5 的6-12组主题词（政策/标准/招标/国际厂商）；
   - 时间过滤：WorkBuddy WebSearch 用 `freshness` 参数（周报d7/半月m1/快报d5）；**其他平台无 freshness 时，把时间词写进查询串**（如"2026年11月26日 27日"、"最近三天"），并对结果逐条核对日期过滤；
   - **预算约束（务实承诺）**：核心10家逐家必查；watch 153家不承诺每期全覆盖——按方向轮转监测并在 search-coverage.json 如实记录"未检索"名单，宁可声明漏查不得假称已覆盖。WebSearch 被平台审批拦截时，启用备用多源调研通道（如会话内 domain_search 类工具），并同样记录覆盖情况。
4. **去重**：对照 events.jsonl 与上期报告，已覆盖不重复写；衔接期条目标"补收"。新事件**必须追加写入 events.jsonl**（含结构化 source 字段）。
5. **记录检索覆盖**：每期结束更新 `state/search-coverage.json`（结构见该文件），明确区分"已检索未发现"与"未检索"——报告中如实注明未覆盖范围。
6. **生成HTML报告**（模板见 templates/templates-all.md §模板一），固定章节（**按动态属性分类，2026-11-26定稿，不再按业务方向分章**）：
   Header（监测区间+按属性计数的数据卡片）→ 〇本期一句话 → ①中标与订单（表格：日期/企业/项目与金额/形态信号）②产品发布与技术动作 ③政策与标准（表格：日期/事项/意义）④资质与认证 ⑤安全事件与风险警示 ⑥市场情绪（可选）→ 对中安云科启示（可执行建议）→ 待复核 + 本期检索覆盖说明。
   样式：渐变header、卡片grid、重点条目橙色顶边、badge标签（hot/warn/new）、斑马纹表格、洞察盒。每条必须有日期+来源性质标注（单一信源→待复核）。
7. **交付**：优先用平台文件交付能力（WorkBuddy为present_files）呈现报告；环境不支持时，告知报告已保存至 outputs/ 并给出文件路径。附"三条最重要线索"文字总结（preferences.md格式）+ 主动询问回填台账/压周报。
8. **状态持久化**：更新 research-state.json（last_report_id/covered_until）；平台有会话记忆机制（如 .workbuddy/memory/）则追加当日日志，没有则跳过并确保 research-state.json/events.jsonl/报告文件三件套已落盘。

### 变体
- **增量快报**（窗口仅3-4天）：章节精简，聚焦单一主线（如"10.30收官日"），快报体量减半。
- **周报摘要**：300字左右大白话，数字先行（金额/百分比/排名），给领导可直接转发。

## 流程B：资质对比Excel

1. **数据一律先用技能包内 `data/` 快照**（权威优先级见 data/README.md）：中安云科=zayk_certs.json+用户确认口径（有效34）；竞品有效数=competitor_gm.json（refreshed_at 最新者优先）；163家企业名录=config/companies.json；summary_all.json 的 gm 为**总数口径**禁止当有效数排名。
2. 如需刷新：运行 `python scripts/update_data.py`（含结构校验/骤降保护/自动备份）；刷新后必须跑 `scripts/validate_data.py`（0错误才可用）。用户磁盘原件（如 D:\市场营销内容\）仅当用户主动要求比对时读取；**文件不存在时直接用包内数据继续，不中断任务**。
3. 竞品数据补充：scctc 接口逐家拉取（knowledge.md §1.1，注意TLS坑位），只保留有效证书做对比口径（状态"待确认"不计入）；竞品范围按OSCA名单+用户指定。
4. 联网补充企业级资质（ISO/FIPS/BSI等），标注来源与日期。
5. 按 knowledge.md §2.2 结构生成13个sheet（总览→排行榜→中安云科→10竞品），遵守 §2.3 排序编号规则与 §2.1 坑位规则。
6. **先给大体结果（文字）让用户确认，再成表**——用户明确要求的顺序。
7. 渲染验证：PowerShell ASCII脚本 + Excel COM 读 cell.Text 抽查（可选，改动大时执行）。
8. 交付后等用户反馈迭代（历次反馈均为格式类：加宽/合并表头/换排行榜口径）。

## 流程C：单项资质对标（以IPv6为例）

1. 逐家拉取竞品该资质明细（接口+搜索双通道），形成产品清单JSON/表格。
2. 与中安云科现有清单对照，产出：数量对比 → 缺口分类（按招标出现频率分P0/P1/P2）→ 卡标高危产品族识别。
3. 策略输出必须包含：①补证优先级路线（含送测提前一季度的时间倒推）②投标应急对策（证书名称逐字对齐招标文件、联合体、单一来源论证）。
4. 可选落成【对标补证矩阵】sheet（需用户确认）。

## 流程D：台账回填

目标文件：用户指定路径的《2026年市场调研日常周常台账.md》（用户环境中常见位置：桌面/钉钉文档同步副本）。

1. **降级策略**：文件可访问→按既有格式追加；文件不可访问→生成回填内容块（按 templates/templates-all.md §模板二/三格式）交付给用户自行粘贴，并写入 state/research-state.json 备忘，**不得因找不到文件而中止任务**。
2. 文件可访问时：先读台账，确认既有章节结构（`# 二、每日市场调研记录`、`# 三、周度汇总`）与最近条目位置。
2. **每日记录**插入到"二"章节末尾（"三"之前），五段式模板见 templates/templates-all.md §模板二。
3. **周度汇总**追加到文件末尾：按日期区间命名（D10），含汇总表+3.1动态表+3.2判断表。
4. 纯追加不改动原文；条目注明对应报告文件名与出具日期。
5. 单一信源/未核实内容写入"待复核信息"栏。

## 流程E：专题深挖（按需）

政策专题（如新规收官）、财报专题（三季报盘点）、展会专题（安博会/乌镇）、对标专题。套路：窗口内集中检索该主线→时间线整理→竞品位置图→我方行动清单。
