# 用户长期偏好（references/preferences.md）

> 来源：用户级长期记忆 + 本会话确认。冲突时以本会话最新确认为准（见 decisions.md）。

## 沟通与输出

- 中文沟通；**简洁直接、结构化、高信息密度**，分条呈现；不需要多余客套。
- 向领导汇报：简洁直白的大白话总结；详细调研后提炼**关键词列表**供报告/PPT复用。
- 最终文字总结模式（已验证有效）：**"三条最重要线索"加粗标题+展开**，其他要点用速览表，结尾给"今天就能做的事"并主动询问下一步（回填台账/压周报/起草选题）。
- 先给大体结果，用户确认后再归类成表格（资质类任务）。

## 表格规范（强规则）

- 表头一律横向，禁止竖排/旋转文字（用户明确反感"歪着头看"）。
- 对照/对比表用 ✔ / ✘ / △；产品类矩阵用 ✔。
- 「序号」列=连续编号1..N；原始编号另设「名录序号」列。
- 排序规则显式可验证：主键+并列组次级键，口径写进说明页。
- 表格要宽、留足边距、信息层级清晰；表头该合并就合并，不留无用空表。
- 表格按重复频次排序。

## 报告规范

- 连续编号（周览类）；明确不重复已覆盖内容。
- 每条信息含来源、发布日期、生效日期、政策方向；按日期窗口筛选。
- 单一信源标注"待复核"，不当已核实事实写。
- 报告文件命名：`2026年X月第N周竞品动态调研报告（MM.DD-MM.DD）.html`；快报：`2026年X月X日竞品动态快报（MM.DD-MM.DD）.html`；存 outputs/ 目录。

## 工作习惯

- 行动前常要求"先别动"，先整理文档说明步骤。
- 提醒类任务：按时check-in提醒（政策/竞品/内容/活动），只催促不代填数据。
- 偏好自行上传发布仓库改动，不让AI代发布（GitHub: Pixelunit-design/Sinocipher-work）。
- 工作区命名使用方括号；Windows + Git Bash 环境。
- 周五常需周报摘要（300字左右）。
- 收集信息需联网补充校准；没有的资质要如实告知并搜索。
