# 竞品公众号内容监控（Competitor WeChat Monitor）

监控2026重点企业名单（约163家：中国95+国外68）的公众号/内容源动态，按信息类别分类汇总，生成日报/周报/月报。

## 数据层（skill 内置，改名单只改这里）

**数据来源只有一个：skill 自带的 `assets/data/` 目录**，随 zip 一起分发，不依赖任何本地存储路径（每个人存储习惯不同，skill 自包含才能开箱即用）。

| 文件 | 位置（skill 内） | 用途 |
|------|------|------|
| 竞品名单 | `assets/data/2026重点企业截止8月初更新版.xlsx`（Sheet: `2026重点企业汇总`） | 企业清单：国家/企业类别/企业/企业全称/主营定位 |
| 内容源对照表 | `assets/data/2026重点企业微信公众号与内容源汇总_163家_v2.xlsx`（Sheet: `163家企业内容源汇总`） | 公众号名称/ID、官网博客、X账号、内容获取渠道、确认状态 |

**运行时实时读取这两个文件，禁止把企业名单硬编码进本skill或任何脚本**——用户随时会增删企业，硬编码会导致名单漂移。

加载竞品清单：运行 `scripts/load_competitors.py --out competitors.json`，输出统一JSON（含国家、板块、公众号ID、获取渠道、状态），后续流程基于该JSON工作。

## 内容获取工作流（三层降级）

1. **检测本地服务（最优）**：GET `http://localhost:5000/api/admin/status`，若在线则用 wechat-download-api 全量拉取各公众号文章列表（`GET /api/public/articles?fakeid=xxx`）和RSS（`GET /api/rss/{fakeid}`），方法详见 `references/methods.md` 第二节。
2. **搜索聚合（默认）**：对重点竞品按类别做 WebSearch（加 `freshness` 时间窗），配合"TOP7·厂商资讯聚合"等聚合类公众号文章、FreeBuf/安全客/嘶吼/安全牛/cn-sec 转载监测、巨潮资讯网公告。
3. **UA伪装法抓正文（核实）**：搜索命中 mp.weixin.qq.com 文章链接后，用 `scripts/fetch_mp_article.py <url>` 抓取完整正文核实细节。用法与红线详见 `references/methods.md` 第一节。

国内企业与国外企业分开处理：国内企业走公众号渠道；国外68家无公众号，走官网博客RSS + X + 行业媒体（对照表中已配好各家的渠道）。

## 分类体系（9类，生成报告时固定使用）

1. 新产品发布/认证 2. 中标项目 3. 会议与活动 4. 安全漏洞与威胁 5. 政策法规与标准 6. 融资并购与战略合作 7. 行业报告与市场分析 8. 资本市场动态 9. 其他值得关注

## 报告生成规范

- 用 `assets/report-template.html` 作为骨架（渐变头部、概览卡片、分类分区、彩色条目、标签系统），条目按"公司名 | 事件 | 来源"结构写。
- 每条动态注明来源与日期；宁缺毋滥，未经核实的不写"确认"。
- 文件命名：`YYYY年M月D日网安企业公众号动态{日报|周报|月报}.html`，写在用户指定的输出目录；未指定时使用当前平台约定的交付目录，完成后使用当前平台可用的文件链接或预览方式交付。
- 周报/月报结尾附"本周/本月核心趋势"段落（3-5条，大白话+行业判断）。
- 【抓取内容仅用于内部存档/竞品分析参考，不得搬运发布】。

## 备注说明：以后怎么修改数据来源

**数据只有一处：skill 内的 `assets/data/` 目录**，改数据永远只动这里，不存在其他副本。

### 场景A：常规增删企业（文件名不变，最常用）
1. 打开 `assets/data/` 下两个 xlsx 直接编辑：
   - **竞品名单**（Sheet `2026重点企业汇总`）：增删行，必填列——国家、企业类别、企业、企业全称、主营定位
   - **内容源对照表**（Sheet `163家企业内容源汇总`）：同步增删行，维护公众号名称/ID、官网/博客、X账号、内容获取渠道、状态（已确认/未确认）
2. 校验：运行 `python scripts/load_competitors.py --out test.json`，看"竞品总数"是否符合预期、有无报错
3. 新增企业若无公众号信息：先搜索补录进对照表，状态标"未确认"，不要留空

### 场景B：名单整体换新版文件（如"截止9月底更新版.xlsx"）
1. 新文件放进 `assets/data/`，删除旧文件
2. 同步改两处文件名引用：
   - SKILL.md「数据层」表格中的文件名
   - `scripts/load_competitors.py` 顶部的 `LIST_NAME`（对照表对应 `SOURCES_NAME`）
3. 校验通过后重新打包分发

### 场景C：更换数据格式/来源（如换成CSV、在线表格导出）
修改 `scripts/load_competitors.py` 中的 `load_list()` / `load_sources()` 读取逻辑，输出JSON的字段结构保持不变（country/cat/name/full/position/wx_name/wx_id/blog/x_account/channel/status）。

### 硬约束（违反会导致脚本读不到数据）
- **Sheet 名不可改**：`2026重点企业汇总`、`163家企业内容源汇总`
- **列名不可改**：国家、企业类别、企业、企业全称、主营定位、微信公众号名称、微信号(ID)、官网/博客、X(Twitter)、内容获取渠道、状态
- **禁止在任何脚本中硬编码企业名单**
- 改完数据重新分发前，先跑一遍校验命令确认无误

## 维护指南

- 调整竞品目录：**直接编辑 skill 内的 `assets/data/` 两个xlsx**（名单文件版本升级如"截止9月底更新版"，用新文件替换旧文件后同步更新本文件中的文件名引用）；若新增企业无公众号信息，先搜索补录进对照表。具体步骤见上方「备注说明」。
- UA伪装法失效（返回验证页/正文容器缺失）：如实告知用户，切换搜狗微信搜索+行业媒体转载兜底，并提醒用户方法可能被微信调整。
- wechat-download-api 部署/登录过期/代理池配置：见 `references/methods.md`。

## 分发给同事（开箱即用）

1. 把 `competitor-wechat-monitor-vX.Y.Z.zip` 发给同事，使用 WorkBuddy 时，按该产品实际技能目录安装；原包约定路径为 `~/.workbuddy/skills/`。解压后应为 `<技能目录>/competitor-wechat-monitor/SKILL.md`，避免多套一层目录；其他平台按其技能安装方式处理。**数据已内置**。运行环境要求：Python 3.8+、`pip install openpyxl`。
2. **服务层按需部署**：同事可选部署 wechat-download-api（`start.bat` 或 Docker，见 methods.md 第二节，需公众号管理员扫码）；不部署也能正常用搜索聚合+UA伪装法跑日报/周报。
3. 同事维护自己的名单：直接改解压后的 `assets/data/` xlsx（每人可维护自己版本），或升级时直接安装你发布的新版zip。
4. 版本管理：版本号在 SKILL.md 的 `metadata.version` 字段与zip文件名双重记录；改动skill（含数据）后递增版本号再重新打包分发。
