# 信息获取方式备忘录

本备忘录合并已使用的信息获取方式与可用的补充手段，供每期检索时参考。具体调用以当前环境实际可用工具为准，不能把备用方式写成已经执行的操作。证据是否足以入稿，继续依照 [核验与异常处理](verification.md) 判断。

## 一、首要入口：官方平台关键栏目

- 按主文件的版本优先顺序，读取用户本次指定清单或包内[sources/安全资讯来源清单V3.md](sources/安全资讯来源清单V3.md)，围绕数据安全、密码技术（包括零信任）、CA相关监管机构、标准机构及官方发布主体建立本期重点栏目表。优先查看通知公告、政策文件、政策解读、标准发布/征求意见、司局业务动态；国内先查，国际仅少量补充。按信息价值和实际热度搜集筛选，入选后才按七类资讯属性归类，不按七类逐项搜料或凑栏目。
- 从官网首页、网站地图或已核实栏目链接进入列表，按列表日期及分页检查指定窗口，打开相关正式内容和附件。不要先给每一项套主题关键词，导致名称中没有“安全/密码/身份”但实际相关的官方文件漏查。首页推荐卡片不等于完整栏目，要检查实际通知或业务列表。
- 栏目未显示本期内容或读取失败时，先检查其他官方版本、栏目分页、正式附件或官方发布账号，再用站内搜索、限定官网域名的查询、文件名和文号补漏。关键词检索是补充路径，不能用搜索结果摘要冒充已检查官网栏目。
- 完成官方主线覆盖后，再查看清单内媒体及用户参考平台，补充事件事实并核对传播范围，避免第三方标题和解读预先决定候选池及结论。厂商参会报告和单项中标可按核实后的独立事实使用，不因渠道或企业参与自动排除。
- 工具支持时使用日期过滤辅助补查，但不能用最近七天代替用户明确的更长区间；索引日期不是原始发布日期，过滤也不能代替事件去重。官方正式解读按其自身首次正式发布或实质更新日判断，不沿用旧政策日期，也不采用普通转载日期冒充新解读。
- 只记录实际检查的机构、栏目链接、窗口覆盖和结果；不宣称已经遍历全部来源。工具返回摘要或较长正文时仍按实际内容判断已读程度，不把可检索到写成已读完整原文。

## 二、内容读取：公开网页与附件

| 方式 | 用途与使用条件 |
| --- | --- |
| 网页打开与搜索工具 | 优先打开官网栏目列表及原文；搜索用于定位官方入口、站内补漏与传播交叉核对。某些环境称为WebSearch/WebFetch，使用当前可用等效工具。 |
| 同机构电脑页、移动页或其他官方版本 | 原页超时或解析异常时补读，确认机构归属及内容是否一致。 |
| 本机Python `urllib`、PowerShell `Invoke-WebRequest` | 历史任务使用过的公开网页请求方式；网页工具失败时可尝试，以实际响应正文为准。单次请求并非持续运行或批量遍历网站的采集系统。 |
| 正式附件、官方标准数据库 | 核对文件正文、标准名称、状态、适用范围和日期；只读题录时不扩写技术条款。 |
| 清单允许渠道的完整报道或转载 | 可支持报道中明确证实的事实；政策与标准优先回溯发布机构，原页受限时按核验参考处理，区分承载渠道和原发机构。 |

每条入稿资讯均须有可追溯、足以支持正文的已读证据。政策重点核对文件名称、文号（如有）、日期、效力、对象、条件与期限。官方解读须识别正式发布主体、独立文章及日期；企业解读不能替代官方新解读。行业动态可依据符合来源规则的完整报道，厂商报告与采购公告分别按其实际主体和范围核实，不要求所有消息都另找政府文件，也不能仅凭摘要编写正文。

原页失败时依次尝试适用的其他官方版本、附件、数据库或本机请求，不必机械穷尽全部工具。记录成功与失败的实际结果；遇到访问验证或登录限制，不以更换请求方式冒称已经读到正文。仍不足以支撑关键事实时，缩小表述、标待核或舍弃，不能转用大量国外素材补数量。附件无法解析时，只写官网通知本身能证实的事实。

## 三、本地参考与历史证据

- 读取用户提供的文档、截图、链接和摘录，逐条纳入候选池，与主动检索内容统一核验、去重和排序。其来源平台可以在清单外，经核实后即可采用，无需清单内另有报道；此来源例外不免除事实核验、主题、时点、国内比例与竞品排除要求。
- 读取可取得的往期周览和核验记录，以事件、文号或标准号识别重复及实质进展；不能以“最近七天”过滤代替去重。
- 同一会话或历史记录中已核验的素材可以复用，但必须能找回来源链接、已读事实、日期与状态记录。仅有记忆或旧稿中的“已核验”自述不够。复用时重新判断本期资格；涉及可能变化的状态或期限、证据冲突以及新进展时补查，不把复用冒称本轮重新读取。
- 不把已保存的核验摘要当作完整原始网页归档。未实际归档全文时，不声称拥有全文快照；未取得的往期不计入已去重范围。

## 四、覆盖范围与能力边界

- 默认工作方式是逐期覆盖重点官网栏目、定点读取原文并补充检索，没有因此部署常驻爬虫、全站批量遍历程序或定时巡检任务。官网栏目检查是主要入口，不应仅在关键词检索失败后才做。
- 来源清单约束主动检索选材；用户提供的清单外参考经核实可以入稿。遵循清单不等于已逐站轮询全部栏目，也不应成为拒绝已核实参考资讯的理由。
- 搜索索引可能延迟、遗漏或标错时间，官网栏目优先可降低第三方信息干扰，但仍不能保证完整覆盖或实时发现当天全部消息。未检得不等于没有发布。
- 默认使用公开可访问内容。登录、付费数据库和需要账号的系统是否可读，取决于实际工具与授权；不能宣称已经访问，也不能把当前未具备访问条件写成永久技术上不可能。
- 固定周期巡检、自动化提醒、Connector接入或批量采集属于另行配置的能力。普通周览任务不代表这些机制已经建立，不能在备忘录中虚构配置或执行结果。

## 五、记录实际获取方式

在既有内部核验记录中简记本轮实际读取方式、结果及证据边界，例如“网页正文可读”“本机请求成功”“仅摘要”“附件未解析”“沿用某日已核记录”。保留事项、链接和关键日期，不保存冗长搜索日志。对用户说明过程时据此陈述，不能把尝试过、成功过、预留可用和本轮实际执行混为一谈。文章仍按既定格式交付，影响使用的整体缺口在文末集中说明；具体候选的未采用或待核原因按 [参考资讯取舍与未采用说明](selection.md) 列在同篇底部，不逐条跟随入稿新闻加入获取过程。
