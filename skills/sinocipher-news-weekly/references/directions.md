# 业务范围、资讯属性分类与面向读者

编写常规周报前阅读。先按业务相关性、信息价值和实际传播热度筛选，再将入选事件按资讯自身属性归类；分类不是检索任务清单，不为填栏目反向找料。

## 一、业务范围

业务范围为数据安全、密码技术（包括零信任）、CA。数据安全包括数据全生命周期保护、个人信息保护、授权与安全流通；密码技术包括密码算法、密钥管理、加密签名、密码应用与测评、后量子密码，以及零信任相关的持续验证与访问控制；CA包括电子认证、数字证书、PKI、证书签发使用撤销和相关身份核验、电子签名应用。

三项业务用于判断关联性，不是三个强制栏目，也不沿用密码安全、数据安全、身份安全、网络安全四方向。一般产业宣传、仅涉及网络设备运行而缺乏上述业务关联的消息，不因含有“安全”而自动入选。账号口令不等于密码算法；安全能力认证证书不等于CA数字证书。

## 二、七类资讯属性

| 分类名称 | 收录内容 |
| --- | --- |
| 法规政策与监管动态 | 法律法规、监管通知、政策解读、专项治理、监督检查及整改要求。 |
| 标准规范与技术指南 | 国家标准、行业标准、团体标准、实践指南的发布、修订、征求意见及实施。 |
| 官方申报与资质通道 | 试点申报、项目征集、资质认定、认证测评、备案办理、服务机构遴选、奖项申报等。 |
| 行业会议与交流活动 | 新发布的会议通知、论坛展会、技术研讨，以及会议中有实质内容的成果发布。 |
| 技术研究与实践进展 | 密码算法、后量子密码、零信任、数据保护、数字证书等领域的研究成果、验证与实践。 |
| 行业应用与采购动态 | 政企应用建设、采购要求、单项中标、服务机制及行业应用变化，保留有价值事实，排除商业宣传。 |
| 其他相关资讯与动态 | 与业务有实质关联、符合核验及价值标准，但确实不属于前六类的资讯。 |

分类按事件的主要动作和内容判断，不按出处或标题关键词机械归类。同一事件只入一个最相关栏目；例如以申报条件和办理期限为主的试点通知可归申报通道，不再复制到政策栏目。其他类不放无关、待核或低价值内容。只展示有入选资讯的栏目，不强制七类齐全，不设每类条数配额；正文全篇6—10条的硬性总量按主规则执行。

## 三、面向读者

| 读者群体 | 典型岗位 | 核心关注 | 优先级 |
|---|---|---|---|
| 政企信息化与安全管理人员 | 信息中心主任、网信办负责人、CIO、CISO、安全负责人 | 政策合规、密评整改、项目预算、建设方案、验收风险 | 核心 |
| 信息安全与技术实施人员 | 安全工程师、系统架构师、网络运维、DBA、信息中心技术人员 | 密码设备部署、技术选型、性能影响、系统对接、故障处理 | 核心 |
| 系统集成与解决方案人员，含售前 | 售前工程师、解决方案架构师、项目经理、集成商技术负责人 | 产品组合、方案设计、行业解决方案、招投标技术要求 | 核心 |
| 测评与合规咨询人员 | 密评工程师、等保测评人员、合规顾问、安全咨询人员 | 法规标准、测评要求、常见不符合项、整改方法 | 重点 |
| 密码技术与安全行业从业者 | 密码研发工程师、PKI/CA工程师、安全研究员、技术专家 | 后量子密码、全同态加密、密码算法、前沿趋势 | 重点 |
| 采购与项目管理人员 | 政企采购人员、招投标专员、项目建设负责人 | 采购清单、产品资质、选型依据、建设成本、项目交付 | 补充 |
| 销售与客户拓展人员 | 销售人员、客户经理、行业销售、销售负责人 | 适用客户、需求变化、沟通切入点、项目准备节点和需求识别 | 明确覆盖 |

写作要求：
- **读者画像只用于编辑内部判断**（评估某条消息对各身份读者的实际影响、决定取舍与排序），**不得把画像身份写进正文或小编评论**——不出现"售前可…""销售可…""对售前和销售而言…"等指名表述，读者根据信息和评论自行得出符合自己身份的结论。
- 预算、采购需求和行业机会必须有具体证据，不能从一条政策推导客户必买、预算增长或中安云科已有某项产品能力。
- 文章保持管理人员能够理解、技术人员能够继续判断的表达；不机械地逐类读者展开，也不按读者拆成多份文章。
- 成稿后按[严格读者模拟](editorial-review.md)逐类审读；语气、事实条件、阶段与隐含误导一并检查，不能只查禁词。
