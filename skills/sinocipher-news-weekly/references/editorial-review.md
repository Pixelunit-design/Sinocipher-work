# 正式资讯写作与读者模拟核对

每次交付前必读并执行；这一步检查内容质量，不替代原文核验。读者画像用于内部判断，模拟过程及检查表不写进发布稿。

## 1. 热点资格与正文资格分开

- 热点须是本期在多个不同平台有实际报道或转载，并具有明确公共或行业关注意义的事件。至少核到两个不同发布平台的对应内容；同一平台电脑/移动页、网址变体或多个搜索结果不算多个平台。
- 官方首发加其他平台的实质报道或转载可作为传播依据。同一通稿的跨平台转载能证明传播范围，但不能当作多个独立事实来源。记录各平台链接、日期、传播的是哪个具体事件及同源关系。
- 官方权威、政策优先级、内容已核实、与业务有关，都不自动等于热点。窄众机构公告、报名受理调整等可以留正文；没有实际多平台传播依据不能填入导览，更不能用平台首页、机构数量或“近期很热”代替证据。
- 标题概要也应围绕经核对的热点。导览至少4条不重复热点，同主题相关进展可以合并，合并后仍须至少4条；提供具体新增信息，与标题保持信息差。热点不足4条继续核查，不拆同一事件、不把一般通知改名为热点；仍不足时在文末集中标待补齐，不能宣称完整交付。每条普通文字单独成段，不加粗、不加行首短横线、项目符号或条目编号，由用户自行调整格式。

### 导览篇幅与信息密度

以用户提供的四条短讯样例为风格标准，样例主体文字约40—55个可见字符。实际导览通常约40—60字，每条一句，直接叙述主体、动作与关键事实，用数字、文件状态、具体期限或实质条件体现信息量；这是一项篇幅参考，不为凑字数删除事实条件或填入套话。

不采用“概括性小标题。再展开解释”的两层写法；同主题的多项真实进展可用分号、冒号或并列短语压缩。每条单独成段并空行分隔，继续执行用户明确的无加粗、无行首短横线要求，不照搬样例中混用的列表符号。样例里的政策、期限及技术断言不是事实证据，未经核实不写入成稿。

## 2. 正式公开语气

- 每条正文以真实主体、动作、对象、进展和关键时间组成，直接叙述已核实的公开事实。例：“11月18日，某管理机构公布项目成交结果，服务按成功核验次数结算。”
- 不写“文章建议先盘点……”“笔者认为……”“本文梳理……”“小编建议……”等编辑或读书摘要式引导，不把通用建议凑成新闻。若一条研究仅剩观点和建议、没有可报道成果或正式动作，应更换选题；不能删掉“文章建议”后把同一观点伪装成官方要求。
- 可以准确转述正式文件、解读和发言，但归属必须清楚。官方解读用“某部门发布的解读明确/说明”；企业报告中的发言归企业或实际发言者，不能升级为官方、大会或行业共识。
- 小编评论直接概括本栏目的变化、共同影响、条件和实施难点，保留判断与事实的边界。不用“对售前和销售而言”“技术人员应”“销售可关注”等读者点名话术，不布置岗位任务。
- 公告本身的适用对象仍要保留。写“申报主体须为运营单位”“金融App运营机构应落实……”是事实范围；写“作为售前应如何……”是读者点名，两者不能混淆。

## 3. 栏目编号与正文总量

先按价值与热度选出全篇6—10个独立事件，再按资讯属性归类。只展示有入选内容的栏目，不设每类条数配额。栏目标题用“一、二、三……”连续编号，各栏目内按价值排序，从“### 1. ……”重新开始；小编评论不编号。核正文总量时，标题、导览、评论、未采用及来源说明不计数；同一事件不同写法、转载及跨栏重复只算一次。不足6条须继续补查，仍不足明确标为待补齐草稿；超过10条按价值择优，不能把额外正文放在末尾作为备选。

## 4. 严格读者模拟：逐类审读，集中改稿

对成稿的标题、全部导览、每条正文、各栏目评论分别执行以下检查。不能只做一次关键词扫描后宣称通过。

| 内部模拟读者 | 必须核对的问题 |
| --- | --- |
| 政企信息化与安全管理 | 能否分清已实施要求、草案、官方解读、会议事实？适用对象、变化与期限是否足够明确？有没有把个案升级成全国政策？ |
| 信息安全与技术实施 | 技术对象和动作是否准确？能否区分已验证成果、公开议题与一般建议？有没有去掉来源归属后虚构“必须这样做”？ |
| 系统集成与解决方案，含售前 | 能否从事实判断场景、接口、条件和验收依据？文章是否把准备建议冒充采购义务，或直接点名该岗位布置任务？ |
| 测评与合规咨询 | 文件名称、文号、性质、状态和例外是否正确？新官方解读是否独立核时？是否拿厂商解读当正式解释？ |
| 密码与安全行业从业者 | 成果和研究是否有具体可核进展？是否靠“某文建议盘点”凑新闻？术语和演讲主体是否准确？ |
| 采购与项目管理 | 单项成交的价格、计费条件、履约范围是否限定到该项目？有没有省略条件、推成统一行业价格或全国收费变化？ |
| 销售与客户拓展 | 能否自行理解相关行业和业务变化？是否有无证据的预算、订单、增长预测，或只对某一岗位说话的评论？ |

处理顺序：

1. 逐条读事实：指出该条的真实主体、动作、时点、对象及关键条件，与证据对应；缺失或冲突回核原文。
2. 通读公开语气：检查是否出现编辑摘要、岗位喊话、泛化建议、宣传口吻，或借删除归属词将观点变成事实。
3. 核热点：确认导览至少4条不重复热点，每条及标题热点均有多平台传播依据，且传播的确为本期对应事件；导览普通文字分段，无加粗及行首列表标记。
4. 核读者理解：按上表逐类审读，记录有问题的具体条目及可能误读；不要求为每类读者另写一段内容。
5. 修改后重读受影响的正文、评论和标题导览，确认没有因200字压缩丢失限定条件；再查栏目编号、条数与文末去向。

内部核验记录至少写明实际审读对象、发现的问题、改法和复核结果。全部合格后交付；有问题就改，不以“符合正式语气”“读者模拟已完成”等无检查内容的自述代替工作。
